# Модель системы в архитектуре

Статус: **внедрено**. Правила заполнения находятся в навыке `doc-arch`, схемы в `doc-architecture/schemas`, проверки в `doc-gates/tools/model.py`.

## Решение

Архитектура описывается объектами системы, а не разделами документа. Spine остаётся сборкой и фиксирует решения. Модель описывает устройство: участники, системы, функции, процессы, сервисы, данные, хранилища, каналы, потоки и узлы.

Нотации TOGAF, C4 и ITIL не выделяются отдельным слоем. Они задают, какие поля обязательны и что считается верным заполнением BMAD:

| Правило заполнения | Откуда |
| --- | --- |
| Слои бизнеса, данных, приложений и технологий, логический объект отделён от физического | TOGAF |
| Система, контейнер и блок вложены друг в друга | C4 |
| Объект ведётся, только если влияет на сервис; у него есть владелец, жизненный цикл и критичность; связи дают анализ влияния | ITIL |
| Сервис обещает потребителю измеримый результат | ITIL |

## Как это проверено

- На «Векторе»: 112 файлов YAML, проверки без блокеров.
- В пакете G01 модель не дала выигрыша, см. `calibration/results-2.md`. Она используется для проверок, анализа влияния и страниц для человека.
